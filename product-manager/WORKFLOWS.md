# 产品经理工作流程模板

## 一、PRD撰写流程

### 执行步骤

```yaml
workflow: prd_writing
steps:
  - name: 需求收集
    sources:
      - 用户反馈
      - 数据分析
      - 业务目标
      - 竞品分析
  
  - name: 需求分析
    outputs:
      - 用户场景
      - 核心痛点
      - 解决方案
  
  - name: 文档撰写
    sections:
      - 背景与目标
      - 用户场景
      - 功能需求
      - 非功能需求
      - 数据埋点
      - 验收标准
  
  - name: 文档评审
    participants:
      - 开发评审
      - 设计评审
      - 测试评审
```

---

## 二、功能上线流程

### 执行步骤

```yaml
workflow: feature_launch
steps:
  - name: 需求评审
    items:
      - 需求说明
      - 技术方案
      - 排期确认
  
  - name: 设计评审
    items:
      - 交互设计
      - 视觉设计
      - 设计走查
  
  - name: 开发跟踪
    actions:
      - 进度监控
      - 问题协调
      - 变更管理
  
  - name: 测试验收
    items:
      - 功能测试
      - 兼容测试
      - 性能测试
  
  - name: 上线发布
    steps:
      - 灰度发布
      - 数据监控
      - 全量上线
  
  - name: 效果评估
    metrics:
      - 核心指标
      - 用户反馈
      - 异常监控
```

---

## 三、竞品分析流程

### 执行步骤

```yaml
workflow: competitor_analysis
steps:
  - name: 竞品选择
    criteria:
      - 直接竞品
      - 间接竞品
      - 潜在竞品
  
  - name: 维度分析
    dimensions:
      - 产品功能
      - 用户群体
      - 商业模式
      - 运营策略
  
  - name: 对比总结
    outputs:
      - 优势分析
      - 劣势分析
      - 差异化机会
  
  - name: 策略建议
    items:
      - 产品方向
      - 功能优先级
      - 运营建议
```

## 四、每日工作流

### 早间例行 (09:00-10:00)

```
□ 检查核心数据指标
□ 浏览行业资讯
□ 回顾今日日程
□ 准备会议材料
```

### 上午工作 (10:00-12:00)

```
□ 需求评审/讨论
□ 文档撰写
□ 设计评审
□ 问题跟进
```

### 下午工作 (14:00-17:00)

```
□ 项目协调
□ 开发跟进
□ 测试验收
□ 跨部门沟通
```

### 晚间总结 (17:00-18:00)

```
□ 今日工作总结
□ 明日计划制定
□ 待办事项整理
□ 邮件/消息回复
```
